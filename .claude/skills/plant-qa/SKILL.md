# Plant QA — 정합성 검증 체크리스트

존재 확인("필드가 있는가")보다 교차 비교("데이터의 값이 화면에 정확히 반영됐는가")를 우선한다. 두 산출물을 각각 검증하면 둘 다 "정상"으로 보여도 연결 지점에서 어긋날 수 있기 때문이다.

## 검증 체크리스트

### 데이터 → 화면 렌더링
- [ ] 모든 식물의 `classification`(과/속)이 화면 어딘가에 표시되는가
- [ ] 모든 식물의 `watering`(주기)이 표시되는가
- [ ] 모든 식물의 `flowering_season`이 표시되는가
- [ ] 모든 식물의 `care_tips`가 목록 형태로 표시되는가 (일부만 표시되고 잘리지 않는가)

### 카테고리 ↔ 필터
- [ ] 데이터의 모든 `category` 값이 필터 옵션에 존재하는가
- [ ] 필터 옵션 중 데이터에 없는 "죽은 카테고리"가 없는가

### 이번 달 추천 식물
- [ ] 화면에 노출된 "이번 달 추천 식물"이 오늘 날짜의 월을 `monthly_pick.months`에 포함하는 식물과 일치하는가
- [ ] 추천 사유(`reason`)가 화면에 함께 노출되는가

### 식별자 연결
- [ ] 카드 → 상세뷰 연결에 쓰인 참조가 데이터의 실제 `id`와 일치하는가 (클릭했을 때 빈 화면이나 엉뚱한 식물이 뜨지 않는가)

## 보고 형식
`_workspace/03_qa/report.md`에 다음 형식으로 기록한다:

```markdown
## 통과
- [항목] — 확인 내용

## 실패
- [항목] — 무엇이 어긋났는지 + 원인이 데이터인지 화면인지 + 고쳐야 할 위치
```

모호한 지적("필터가 이상하다")은 금지한다. 수정 담당자가 다시 조사하지 않아도 바로 고칠 수 있을 만큼 구체적으로 쓴다.
