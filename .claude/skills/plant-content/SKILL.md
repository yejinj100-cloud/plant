# Plant Content — 식물 도감 데이터 작성 가이드

식물 도감 사이트가 필요로 하는 5개 핵심 정보(분류·물주기·개화 시기·관리 팁·카테고리)와 이번 달 추천 식물을 일관된 스키마로 작성한다.

## 왜 이 스키마인가
사이트 빌더와 QA가 이 파일 하나만 보고 화면을 만들고 검증하므로, 필드명과 구조가 흔들리면 화면 전체가 흔들린다. 필드를 추가하는 것은 괜찮지만, 기존 필드명을 바꾸면 화면 렌더링 코드도 함께 깨진다는 점을 유의한다.

## 데이터 스키마

저장 위치: `_workspace/01_content/plants.json`

```json
{
  "updated_at": "2026-09-29",
  "categories": ["관엽식물", "다육식물", "허브", "개화식물"],
  "plants": [
    {
      "id": "monstera-deliciosa",
      "name_ko": "몬스테라",
      "name_scientific": "Monstera deliciosa",
      "category": "관엽식물",
      "classification": { "family": "천남성과", "genus": "몬스테라속" },
      "watering": { "frequency": "겉흙이 마르면 (대략 7~10일)", "notes": "겨울철엔 간격을 더 늘린다" },
      "flowering_season": "실내 재배 시 개화가 드묾 (열대 원산)",
      "care_tips": ["밝은 간접광 선호", "높은 습도 유지", "2년마다 분갈이"],
      "difficulty": "쉬움",
      "light": "밝은 간접광",
      "monthly_pick": { "months": [5, 6], "reason": "초여름 생장기에 분갈이하기 좋은 시기" }
    }
  ]
}
```

- `id`: kebab-case, 사이트 내 상세 연결에 쓰이는 고유 식별자.
- `category`: 반드시 `categories` 배열에 존재하는 값과 정확히 일치해야 한다 — 필터 UI가 이 배열을 기준으로 만들어진다.
- `monthly_pick.months`: 1~12 사이의 정수 배열. 오늘 날짜 기준 월이 포함된 식물이 최소 1개는 있어야 "이번 달 추천" 섹션이 비지 않는다.
- 5개 핵심 필드(`classification`, `watering`, `flowering_season`, `care_tips`, `category`) 중 어느 것도 비워두지 않는다.

## 작성 기준
- 최소 10종 이상, 카테고리를 고르게 섞는다. 한 카테고리에 몰리면 필터가 무의미해진다.
- 학명·과/속·물주기 주기·개화 시기는 실제 원예 지식에 근거한다. 확신이 없으면 보수적인 표현("일반적으로", "실내 환경 기준")을 쓰고, 그래도 불확실하면 해당 식물을 제외한다.
- `care_tips`는 2~4개, 실행 가능한 조언으로 쓴다("잘 키운다" 같은 추상적 표현 금지 — "주 1회 잎에 분무", "뿌리썩음 방지를 위해 배수 잘 되는 화분 사용" 처럼 구체적으로).
- 이번 달 추천 식물의 `reason`은 그 달에 의미가 있는 실제 근거(개화기, 생장기, 분갈이 적기, 초보자 추천 시즌 등)를 든다.

## 부분 갱신
기존 `plants.json`이 있는 상태에서 식물 1종 추가나 이번 달 추천 교체만 요청받았다면, 파일 전체를 재작성하지 말고 해당 배열 요소만 추가/수정한 뒤 `updated_at`만 갱신한다.
